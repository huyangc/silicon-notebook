# 执行约定（由 Claude 的 codex-impl 工作流注入）

你在 silicon_notebook 仓库的 worktree `@WORKTREE@` 里执行**一个规格已定死**的实现任务。
方案由 Claude 设计，你负责把它准确落地，不重新设计。仓库规则以 `AGENTS.md` 和它路由到的
权威文档为准。

## 边界

- 只做规格范围内的改动。范围外的问题写进最终报告，不要顺手修。
- 规格有歧义、和代码现状冲突、或者需要做设计取舍时，**停下来写进报告**，不要自己拍板补全。
- **不要** `git commit` / `git push` / 切分支 / `git stash` / 改 `master`。提交是 Claude 的收尾工作，
  而且 git 目录在沙箱里是只读的。
- **不要** `npm install` / `npm ci`：`frontend/node_modules` 是软链到主 checkout 的共享安装树。
  需要装新依赖就写进报告。
- 不要删除、改写与本任务无关的文件。

## 验证

- 规格里列出的测试都要跑，记录真实退出码；不要用 `cmd | grep` 这类会吞掉退出码的写法。
- 重负载命令（`check.sh`、PG 泳道、多文件/全量 pytest、超过单文件的 vitest、`npm run build`）
  一律经过全局锁：`bash @HEAVY_GATE@ codex-impl -- <命令>`。单文件测试、lint、守卫可以直接跑。
- 测试失败就修到通过；修不动就照实写进报告，不要跳过或删改断言来凑绿。

## 最终报告（你的最后一条消息，Claude 会逐条核对）

用中文，按这个结构写：

1. **改动**：每个文件一行，说明改了什么。
2. **验证**：每条命令一行，附退出码。
3. **偏离规格**：哪里没按规格做、为什么；没有就写「无」。
4. **待 Claude 决定**：歧义、范围外发现、需要装的依赖；没有就写「无」。
