# silicon-notebook KG 抽取与检索产品演示设计

## 沟通任务

面向客户与合作伙伴，通过具体、可验证的产品流程说明 silicon-notebook 如何把半导体工程文档转化为可治理、可检索、可推理且可回溯原文的知识资产，使受众既理解产品价值，也相信其技术边界与可信机制。

## 叙事策略

采用“产品能力主线 + 单条知识旅程案例 + 技术架构深潜”的混合结构。开场建立文件检索与工程知识复用之间的缺口；中段按摄取、抽取、证据绑定、统一图谱和多模式检索逐层展开；后段以查询期推理、治理和规模化能力收束。

## 页序与单页任务

1. 封面：silicon-notebook 让工程文档成为可推理的知识资产。
2. 问题：技术资料很多，真正可复用的知识很少。
3. 全景：文档经过结构化、KG、检索与推理，形成可引用答案。
4. 解析：PDF、Markdown、DOCX、PPTX 转为带来源定位的 SourceElement。
5. 窗口：贪心打包、重叠、自适应大小与并发使长文档处理成本近似线性。
6. 对象：Concept、Claim、Formula、Procedure 构成统一工程知识语言。
7. 接地：对象和关系绑定 SourceElement evidence，无法接地的节点丢弃。
8. 质量：refine、gleaning、去噪、meta-claim 过滤、canonicalize 与类型校验共同约束抽取结果。
9. 图谱：跨文档概念聚类、对象级统一 KG、Personal/Base 两层知识库。
10. 模式：chunk、graph、reasoning 三条检索路径按问题复杂度选择。
11. 召回：关键词/向量、KG 对象、关系、1-hop、PPR、rerank/MMR 与预算装配形成证据网络。
12. 推理：有界多跳、链路校验、chain_trust、Base 权威规则和 follow_chain fail-closed 约束。
13. 案例：一个半导体问题从种子对象、跨文档路径到带编号引用答案的完整旅程。
14. 收束：生命周期、边审核、去重合并、Personal→Base 晋升及 ANN/CSR 规模化索引组成团队知识底座。

## 内容边界

- 只陈述当前仓库已实现且文档记录为完成的能力。
- KG 主对象为 Concept、Claim、Formula、Procedure。
- 无 LLM 时 KG 抽取记录 `no-llm`，不宣传离线启发式伪造知识。
- `chunk` 基线是当前 notebook；KG overlay/PPR 可引入 federated KG 与 Base-backed chunk；`graph`/`reasoning` 使用 federated KG 路径。
- `follow_chain` 仅为查询期临时推导，不持久化为 KG 边，并突出 fail-closed 条件。
- 不重新介绍已退役的 Scenario、Case、Checklist 或 Studio 能力。

## 视觉系统

- 比例：16:9，深墨蓝到近黑背景。
- 主色：冰蓝与电青；强调色：少量暖金；状态色仅在必要处使用。
- 字体：优先使用系统可用的中文无衬线字体；标题 35pt 以上，封面 50pt 以上，正文不低于 16pt。
- 构图：以大标题、单一主视觉和少量高价值说明为主，避免密集 UI 卡片墙。
- 图形语言：发光节点、精细连线、半透明层次、微弱网格与芯片/晶圆式几何纹理。
- 流程图使用 PowerPoint 原生形状；连线先于节点绘制，避免穿过标签。
- 不使用无来源的市场数据、虚构客户指标或夸张性能数字。

## 验收标准

- 输出可编辑 `.pptx`，全部中文产品化文案。
- 14 页形成连续叙事，每页只有一个主要结论。
- 抽取、接地、检索、推理、治理均有具体机制，而非概念罗列。
- 逐页渲染检查，无越界、裁切、意外重叠或标题换行。
- 运行演示文稿结构/画布检查工具并修复问题后交付。
