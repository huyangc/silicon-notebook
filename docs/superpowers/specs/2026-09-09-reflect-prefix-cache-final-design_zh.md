# Reflect 上下文与前缀复用：最终设计及生产实验方案

日期：2026-09-09

状态：设计定稿，供 Claude 实施与后续环境实验；本文交付不代表已实现、已验证提速或批准生产放量。

## 1. 决策与适用范围

采用「稳定指令与任务前缀 + 有界历史增量 + 末尾当前状态 + 达到预算后重建快照」作为目标方案。先实现和测量前缀稳定化，再验证增量记忆和轻量 assessment，分别保留可回退的对照。**不要求模型服务返回 prefix cache、输入 token 或 thinking token 指标；最终选择由答案质量与实测墙钟时间决定。**

三项明确取舍：

1. 不再按“每轮输入越短越好”优化。稳定且被复用的上下文可能更快；每轮删历史、重排证据或改写摘要可能破坏复用。
2. 不按“缓存越多越好”无限保留历史。已缓存的旧内容仍会参与生成，过时判断、无关证据和越来越复杂的状态仍可能增加 thinking 与后续轮数。
3. 没有 provider 命中字段时，只报告“前缀稳定化收益”“策略端到端收益”；不从耗时反推命中 token、缓存命中率、纯 prefill 时间或 thinking 占比。

实现保持既有「意图确认 → 首轮检索 → 单动作 reflect → 最终候选选择 → 合成」结构。第一批生产实验聚焦 Ask 的 standard/deep、有图/无图；Report 和 exhaustive 在共享代码完成后做兼容验证及独立抽样，不由 Ask 结果直接获得放量资格。Knowhow 保持 legacy。

本期不增加原生 tool calling、不转为完整聊天历史、不回放原始 reasoning_content、不增加读证据工具、不新增批量动作、不修改首轮查询宽度及检索范围。用户面对的多轮问答不跨问强行复用旧范围：新问题、新确认契约开启新的任务上下文；固定协议仍可自然复用。

## 3. 原理与可识别性边界

Z.AI 官方说明支持隐式上下文复用，通常可返回 `usage.prompt_tokens_details.cached_tokens`；但本设计以生产端点不返回该字段为正常工作条件。组织请求时采用保守原则：相同内容维持相同文本、角色、消息边界与顺序，把变化放到后面，不依赖“语义相似也能命中”的假设。[缓存说明](https://docs.z.ai/guides/capabilities/cache)

客户端可测到的是：

```text
一次 run 墙钟
  = 首轮工作 + 各轮调用/检索/编排的实际等待 + 收尾重排 + 最终合成等

一次模型调用墙钟
  = 本地调度等待 + 网络/provider 等待 + 输入处理 + 生成 + 校验/重试
```

分项可能交叠，不能把并发子调用耗时之和当成 run 墙钟。没有 provider 细分时，不再进一步拆算。前缀重复只能说明具备复用条件，不能证明 provider 已缓存、路由到了同一实例或命中了特定长度。

GLM 5.3 的当前官方说明为强制 thinking；不把“关闭 thinking”列为本方案必需实验。若生产端点另有能力，另记配置实验，不混入主矩阵。[思考模式说明](https://docs.z.ai/guides/capabilities/thinking-mode)

应用内整份响应缓存、embedding/检索缓存和 provider prefix cache 是不同机制。实验必须关闭测试调用的应用响应缓存，同时保留 provider 自然复用；优先对参与实验的 chat 调用传递 `bypass_cache`，不要通过关闭全局缓存同时改变 embedding/检索行为。`bypass_cache` 不得被标为“关闭 prefix cache”。检索缓存按统一的预热规则处理，并把首次与后续运行分开报告。

## 4. 目标上下文结构

### 4.1 五个块

```text
S：固定协议与工具说明                         system，稳定
C：本次完整问题、确认约束与范围               user，run 内稳定
K：当前阶段的起始快照                         user，阶段内稳定
D1 ... Dn：已完成动作与有效证据/状态增量       user，只追加
Tn：本轮可执行动作、余额、权威当前状态         user，变化放末尾
```

保持少量固定角色消息，例如 `system(S)`、`user(C + K + D1...Dn + Tn)`。D 是服务端结构化观察，不伪装成模型的原始 assistant 消息或原生 tool 消息。不要为缓存把文档内容提升为 system 指令。

相邻调用示意：

```text
R1 = S | C | K         | T1
R2 = S | C | K | D1    | T2
R3 = S | C | K | D1 D2 | T3
```

R2 与 R3 至少在 `S/C/K/D1` 上保持相同；上一轮可变的 T 不留在历史中，而是由小型 D 记录实际结果。不是“整个上一轮请求都成为下一轮前缀”。达到预算后替换 K、清空已折入的 D；S/C 不随压缩变化。

### 4.2 S：工具目录稳定，可用性仍然实时

- 从同一份 `ActionDefinition` 生成工具参数说明，不能复制第二份手写目录。
- 目录是本次 run 在部署、调用方、图与范围条件下**可能**执行的工具的集合；开始时未有候选起点的工具，若后续可能启用，应包含。始终不适用的图工具/调用方禁用工具不用保留。
- 某工具额度耗尽后不删除 S 内的说明；T 给出本轮 `allowed_actions`、相关剩余额度及拒绝原因。静态指令明确：目录是参数参考，T 的本轮清单是可调用集合。
- `ReflectCapabilities` 继续是动态可执行集合的唯一来源。prompt 的 T、解析白名单、执行前校验一致；目录本身不授予调用资格。
- 外层 `chat_json` 注入的 JSON 说明与 schema 也属于实际前缀：一并检查顺序和稳定性，不能只测业务函数生成的字符串。schema 保留现有可识别动作集合，不为省 token 改成逐轮漂移的枚举。
- 本轮余额、stale 数、时间、trace 标识、候选总数等不得插入 S/C/K 前部。

本项改变了模型看到“已耗尽工具说明”的方式，必须监测非法动作率。不能因为结构上更利于缓存，就假定决策效果一定等价。

### 4.3 C：完整任务只表达一次

包含完整权威问题、确认过的方面文本/约束、当前 notebook 与参与范围的必要语义。方面 id 与原文映射在这里固定，T 不再逐轮复制原文。问题里已有完整契约时应复用结构化来源，避免把同一份全文再拼一次。

不静默截断用户内容，不从新增子查询数量反推用户必答项。新用户问题或重新确认契约开启新的 C；不靠复用旧缓存保留已经失效的任务范围。

### 4.4 K/D：精选、有界、展示后保持不变

K 包含本阶段有用证据及历史摘要。D 只在一次动作完成后追加，覆盖：

- 请求身份/目标方面的简短表达；实际状态和新增/重复/失败/部分完成事实。
- 本轮需要模型判断的新增或补充证据卡。
- 已接受的方面状态变化；历史判断标明是模型判断，不冒充原文。

证据卡第一次被展示时冻结文本、位置、身份和顺序。以后遇到更好的摘录，追加一份带版本关联的补充卡；不就地改写旧卡，不把所有卡按最新相关性重排。相同摘录不重复追加。

选择顺序：当前待解决方面的新增材料 → 相关条件/冲突补充 → 必要的已支撑方面代表。数值、单位、否定和适用条件优先。延续 240 字单卡摘录作为起点，不机械缩到旧版 80 字。没有原文的 KG 抽取字段仍标为抽取摘要。

仅存在于池中、尚未展示的材料不获得“模型见过”的资格；新增绑定资格必须在最终渲染后登记。候选池、曾展示、当前可见、合成接纳、答案引用五种状态保持可区分。历史原文被压缩移出当前窗口，不应清空候选池或既有合法绑定；本轮要重新判断某方面时，可从已有内存池恢复有关卡片，不新增读取工具或 LLM 摘要调用。

旧的候选摘要在 `prefix_delta` 中被统一证据投影替代。还没做成证据卡但影响执行的状态，必须显式进入 T，不能随摘要删除而遗失。省略材料要有计数披露；不把“本轮没有展开”说成“没有找到”。

### 4.5 T：短而明确的当前事实

保留本轮 allowed actions/额度、全部必答方面的简短状态、当前绑定代表键、待解决缺口、枚举 scope/计数/完整性/截断、未执行确认方向以及已有大纲/overflow 的必要事实。普通题重点展开下一步有关的 1–2 个缺口，其余方面不从状态列表消失。

完整大纲的现有全量提交语义不变，穷尽档 T 仍需提供当前完整结构与未接纳绑定。状态块整体不能粗暴字符串裁尾。每个状态拥有者继续按现有输入/协议上界提供投影；用户约束和授权范围不是可压缩历史。

S 规定：T 中的服务端当前状态优先于 K/D 中已经过时的观察；历史成功不能覆盖当前不可用、旧 complete 不能覆盖已知 conflict。取消、范围失效或材料不可再使用时，立即走现有边界或重建投影；不为了前缀稳定继续发送失效材料。

## 5. 信息预算与压缩

### 5.1 初始配置

保留现有 v2 总闸。新增一个内部部署策略字段，而非前端选项：

| 配置 | 默认/取值 | 说明 |
| --- | --- | --- |
| `REASONING_REFLECT_OPTIMIZATION` | `off`；`off / prefix_snapshot / prefix_delta / prefix_delta_lean` | `off` 是实施基线 v2 原行为；v2 总闸关闭和 Knowhow 均忽略它 |
| `REASONING_REFLECT_DELTA_CARDS_BY_EFFORT` | overview 2、standard 4、deep 6、thorough 8、exhaustive 10 | 单次增量最多新展开的卡；每项 1–16，完整五档、非 bool 整数、单调不减 |
| `REASONING_REFLECT_COMPACTION_TARGET_RATIO` | `0.5`，允许 0.25–0.75 | 重建快照时可压缩材料占对应池子的目标比例，不是丢弃用户内容的比例 |

其余复用已有配置：

- 证据池：overview/standard/deep/thorough/exhaustive 分别 4,000/6,000/8,000/12,000/16,000 字符。**在 delta 模式中，预算计 K 与所有 D 内证据卡总和**，不是每轮再获得一份全额预算；元信息、标题、版本和省略标记计入所属池。
- 历史观察池：`REASONING_REFLECT_STATE_CHARS=6000`，计 K 的可压缩历史摘要与各 D 的动作/历史判断，不能每个块各享 6000。
- `REASONING_REFLECT_RECENT_OBSERVATIONS` 在 snapshot 模式保持旧含义；delta 模式用于重建 K 时保留多少近期详细观察，不触发逐轮滑窗。对照实验先保持现有值 6；选出布局后再比较 2 与 6，避免一次改变太多因素。
- 摘录上限继续使用 `REASONING_REFLECT_EXCERPT_CHARS=240`。

这是供实验的初始值，不宣称最优。字符是代码可稳定控制的预算单位；拿不到可靠 tokenizer 时不按固定比例折算成 token。S/C/T 由自身协议边界限制，不冒充整个输入只有 6000 字符；记录每块实长和整份消息长度。旧文档中的最大可能长度不能作为每次实际成本。

### 5.2 何时压缩、压缩什么

delta 模式第一次构造 K 时也采用目标比例，为后续增量留空间；不会先把首轮池子填满、第二轮立刻重建。必要材料可按下面规则超过目标比例。P 模式仍保持基线的证据选择，不使用这一收缩规则。

只有当待追加 D 将使证据池或历史池超过预算时，才在下次模型调用前重建 K。短循环不按固定轮数强制压缩。更新依赖顺序为：动作完成 → 形成待追加事件 → 检查预算 → 必要时从权威状态与已有池重建 K → 生成当前 T → 调模型。

重建使用确定性代码，零额外 LLM 调用。按目标比例选取：

1. 当前待解决/冲突方面所需证据代表，保住理解下一步所需的条件；
2. 已支撑方面的代表键和必要卡，不保留其全部搜索过程；
3. 近期详细观察，其余折成已尝试/已失败/重复/完整性计数；
4. 未展开与已压缩的计数披露。

完整权威账仍在服务端，不复制出另一套控制检索的状态。若必要材料使目标比例无法满足，可在硬预算内高于目标；若没有空间容纳最小有效新证据，不能每轮反复压缩空转：本 run 的剩余部分回退到 `prefix_snapshot` 的有界证据选择，保留轻量自评与否的原设置，并记录 `context_fallback`。仅回退上下文组织，不丢弃检索结果、不重置预算、不增加模型调用。

## 6. 轻量 assessment：独立实验、独立处理

前三个模式共用实施基线的决策/失败合同，用来比较布局与记忆。`prefix_delta_lean` 在 `prefix_delta` 上增加本节改动，明确作为另一条实验臂，不能把全部收益归因于缓存。

- 常规轮只报告本轮能判断的**方面变化**，没有新判断可省略；不要求重复重述所有已支撑项。
- 选择结束时，在同一次决策内给出可判断的最终变化和缺口；未评估项目保持 unknown/已有状态，不为了补齐账目再专门退回一轮。
- 动作与 assessment 独立校验。动作合法但附带自评有误时，执行合法动作；只接受可明确解释的有效方面更新。未知方面/非法证据键不能取得支撑资格。
- 同一方面完全相同的重复项可确定性去重。相互冲突的重复项拒绝该方面的更新，保留旧状态并披露；不任意取首条/末条。跨项错误不作废其它独立合法方面。
- 超过范围的 evidence_keys 不默默截出一份“已充分”判断；按方面拒绝该次更新并披露稳定原因。gap 超限亦拒绝该方面更新，模型自行生成的错误不会吞掉合法检索动作。
- 省略 assessment 不等于“证据不存在”；需要区分未评估与已确认缺失。沿用并校准 `assessment_omitted` 等现有状态，合成不能把未知自动写成确定缺失。
- provider/JSON 故障、取消、动作参数不合法仍走原有合同；不放宽真实工具执行校验，不新增原始响应修复 LLM。

本期不采用“两轮没新键一律停止”，不把模型自评变动当作清零 stale 的依据，不改变最大步数及工具次数。缺失自评不再产生额外轮之后，相应的 stale 特例自然没有该输入；其余 stale 逻辑不借本项目重写。

终态保留现有 reason 闭集。若未评估方面使既有分类仍为 `model_partial`，同时保留模型真实的结束判断及未评估标记；合成披露“尚未逐项核验”，不能据此写成“资料中没有答案”。这一处文案/状态解释随 L 一起验证，不回写到 B/P/D 的对照行为。

## 7. 与 Claude 的 turn-economy 工作如何合并

实施前对齐该工作的实际提交，避免并行维护两个 executor。公共 bug 修复可以先合入所有实验臂共用的基线；必须保留修复前后 SHA，旧生产表仅作为历史参考。

采纳方向：恢复枚举的规模/范围提示、修正 exact 参数可理解性、准确计时、避免错误自评废掉合法检索。

本设计不接受以下未经逐例验证的简化：

- 无图且单篇就禁用枚举：单篇仍可需要列出表格/公式；`enumeration_rejected` 不能证明枚举整体无用。
- 大联邦自动改成本库：范围收窄必须符合用户语义；允许报告计数、样本与不完整，不能把有界样本签发为 complete。
- 把一个动作返回 300 行直接解释成模型调用了多轮分页，或把聚合 55 行解释成某 notebook 的文档总数。
- 把长 answer 步算成补自评调用：收尾重排可能重新检索，需单独测量。

若公共基线改变了停机/枚举/失败策略，B/P/D/L 四臂都必须在同一公共基线上重新生成结果，不能拼接旧批次充当配对。

## 8. 无缓存字段时的测量合同

### 8.1 必有字段：不依赖 provider

以既有 model-work 调度边界和 rig run 边界为计时点，不复用 trace 相邻步差冒充模型耗时。只扩展必要的计数/闭集字段；优先从现有事件提取，不新增正文日志。

| 层次 | 必有观测 |
| --- | --- |
| 单次调用 | 本地序号、所属实验臂/run/轮次、开始与结束、`call_wall_ms`、状态码、已知重试次数、响应字符数 |
| 上下文 | 各块字符数、总字符/UTF-8 字节数、与上一轮输入的公共前缀长度、压缩/回退次数、当前卡数/省略数 |
| 检索 run | `run_wall_ms`、reflect 逻辑轮数、真实模型调用次数、工具动作数、无效/失败次数、结束原因 |
| 完整 Ask | 检索与合成各自墙钟、全程墙钟、完成/超时/失败、最终质量记录 |
| 实验控制 | 代码/策略版本、模型与配置标签、语料快照签名、档位、题集键、重复序号、臂序、并发、前次调用间隔 |

“真实模型调用次数”包含 schema 修复、传输重试等已知实际请求；若现有 adapter 只能得到逻辑调用数，另记 `attempts_observed=false`，真实数为 unknown，不能与逻辑轮数混称。可取到本地排队时长则单列；取不到不猜。起止使用 monotonic/perf_counter；时间戳只用于分组核对。

公共前缀长度在最终消息序列上比较，包含底层注入的 schema wrapper 和角色/边界。使用确定性序列化计算 `message_prefix_bytes`，有可靠本地 tokenizer 才附 token 值。该指标只是客户端结构指标，命名不能叫 cache hit。

只有总调用墙钟而无 token 也足以跑全部主实验。若 SDK 对流式与非流式兼容有回退，记录实际模式，主比较不要同时改变 streaming 配置。不要为得到 TTFT 强行增加新传输路径。

### 8.2 可选字段

provider 输入/输出/cached/reasoning token、finish_reason、首次流事件/首个可见正文时间。缺失一律 null/unknown；不把 cached 缺失写成 0，也不由响应字符数推算隐藏思考量。通用采集接缝允许将来补字段，本期不等待它们。

实验编号是本地分配的无语义短码；聚合只留计数/闭集值。原题、证据、完整请求和原始响应如确有重放需要，只放操作者控制的 `.local` 私有实验资产，沿用现有 rig 的隐私边界；不进入普通遥测或发布报告。生产凭据/URL 不进入实验配置摘要。

## 9. 三层实验

各层预算和阈值是本方案的初始实验配置，须在跑批前冻结并 dry-run 展示，不写成生产热路径中的字面限制。真实环境调用留给后续实施/实验阶段，本次文档交付不发起。

### 9.1 E1：前缀复用敏感性探针

目的：在相同内容量、相同输出任务、相同模型配置下，检查稳定前缀是否带来可重复的墙钟改善。它是机制线索，不是实际 reflect 质量评估。

使用固定、非敏感的检索上下文样本。输出固定小 JSON，例如 `{"ok":true}`；两臂用相同指令、相同输出上限与相同 schema，模型 thinking 设置不变。内容长度覆盖真实样本的短/中/长三档，不为刷命中而追加大量无关填充。

两臂都有位于最终消息开头与末尾的固定宽度无语义实验标记；标记明确不参与任务，位置与格式相同：

- **stable**：开头标记在一个序列内固定，末尾标记逐次变化；有用正文完全相同。
- **disturbed**：开头标记逐次变化，末尾标记在序列内固定；有用正文仍完全相同。

每个序列使用新的实验标识，避免 stable 序列直接复用前一序列；两臂使用不相同的标识，减少彼此污染。两臂包含相同数量和长度的标记；可取 tokenizer 时匹配 token 长度，不能时只声明字符/字节匹配，并更换标记值重复验证。

开头标记必须在 provider-facing 最终消息的尽可能早位置，不能插在业务 user 段却漏过之前的长 system。实现通过既有 transport 装配的测试接缝完成；业务 service 不直连 provider、不引入第二套 SDK 客户端。接缝默认关闭，不接受公共请求注入，不在生产策略里加入随机标记。

注意：这是“扰动前缀”，不保证清空 provider cache，也不保证关闭服务商的整答缓存或路由优化。缓存块粒度、服务端规范化、thinking 波动都可能影响结果。

初始运行：3 个长度档 × 4 个配对区组 × 2 臂 × 每臂连续 4 次 = **96 次逻辑调用**。区组内随机采用 stable→disturbed 或相反顺序，整体平衡；各序列内部保持连续，记录间隔，不插入并发负载。统一做一次小型连接预热，使用不同正文/前缀，预热成本单列。可先跑 48 次冒烟，但不凭该前缀直接定论。

每序列第 1 次记为“该前缀首次观测”，不是已验证冷缓存；后 3 次为重复观测。主要统计配对区组中两臂重复观测的中位墙钟差与比值，并比较后续相对首次的变化。全部结果和首次成本同时展示；失败/格式不符单列，不只挑快且成功的请求。

新实验标记只用于 E1。在 E2/E3 中不加入逐次随机前缀，否则会主动摧毁要测的自然复用；实际臂序、重复和跨时段测量负责降低环境漂移影响。E1 的标记作用于最长稳定前缀，并不能保证该前缀之后所有内容都不被服务商用其它机制复用。

可下结论：稳定前缀在这个端点/负载/长度下有、无可辨认或不确定的时间收益。**不可下结论：命中率 X%、省掉 Y token、provider 已关闭缓存。**未观察到收益仍可进入 E2，实用布局可能通过其它机制改善实际任务。

### 9.2 E2：固定状态的真实 reflect 对照

目的：把轮数和工具选择反馈暂时固定，检查真实决策任务的单轮成本与行为。

冻结 12 个案例的初始状态与外部给定观察序列：单事实/复杂条件、有图/无图、目录/大集合、失败/重复/工具耗尽。每例 3 个状态点、2 次重复、3 臂 B/P/D，共 **216 次逻辑调用**；资源紧张先跑 6 例 108 次，作为筛选而非放量证据。

| 臂 | 渲染与行为 |
| --- | --- |
| B | `off`：当前 v2 snapshot，作为公共基线 |
| P | `prefix_snapshot`：稳定 S/C，工具可用性与变化状态放末尾；证据/历史选择保持基线内容，允许保留重复展示以隔离布局作用 |
| D | `prefix_delta`：P 的稳定骨架 + 本文有界增量/阶段压缩，去掉重复证据展示 |

P 与 B 的差异包括指令/工具说明布局，不能宣称纯缓存因果；E1 提供独立机制线索。D 与 P 同时比较历史投影，属于上下文策略收益。

每臂按时间顺序重放完整三个状态点，不在臂中途交错破坏自身连续性；臂序按案例/重复平衡随机化。每次调用返回的动作只记录，不执行、不改变下一状态；因此测试的是固定观察下的策略，不是其自洽真实轨迹。人工/确定性核对动作可执行性、是否正确停止、目标缺口、方面绑定，不要求不同臂输出逐字一致。

对初始状态、后续状态、压缩边界分别报告。候选与状态不齐的历史原始 trace 不能直接当成可重放快照；需由已授权的 `.local` 采集或自包含 fixture 构造，缺数据不补造。

### 9.3 E3：真实自主循环与完整 Ask

目的：决定实际采用哪种策略。顺序分两步，减少真实模型预算：

1. 从 E2 选出 P/D 中较有希望且无明显行为退化的候选，与 B 做小批完整 Ask；若 D 无收益，P 可以直接成为候选，不为追求最大前缀坚持 D。
2. 在候选上独立比较轻量 assessment。若候选为 D，使用 `prefix_delta_lean`（L）；若 P 已胜出而 D 被淘汰，先保留 P，不为开启 lean 强行迁入 D，lean-on-P 留作明确的后续选择。

筛选批使用同一组 12 题 × standard/deep × 2 臂 × 1 次 = **48 个完整 Ask**。选出最终候选后，主确认沿用 T0/A/B 冻结题集，至少 30 题 × 两档 × 2 臂 × 3 次 = **360 个完整 Ask**（使用现有 34 题时为 408）。历史 legacy 只作为单独的质量/成本参考，不增加每轮主矩阵的第三臂，也不能替代当前 B。

每道题两臂背靠背，但臂内完整循环连续运行；臂序按重复/档位/题型平衡随机化。默认实验并发 1，不与其它实验争抢同一模型服务；无法控制正常业务负载时，分至少两个时段重复并按时段展示。冻结语料/索引、用户契约、来源范围、模型服务及采样/thinking/输出预算，记录实际配置。

真实循环允许轮数、动作与输出长度变化：这些是策略效果，不能为了归因把它们从端到端主指标中剔除。分别报告每轮成本和整次成本。搜索-only 小批可用于排障；放量判断必须有最终答案与引用。

完整 Ask 沿用已有一次性测试库路径，生产模型可作为服务端点；不要往用户主库写测试答案。只读主库 search 必须沿用既有只读断言。实验不切换线上全局配置，两臂采用独立的运行配置。

## 10. 分析方法与采用标准

### 10.1 统计方式

- 主指标：完整 Ask 的配对墙钟比 `candidate_ms / baseline_ms`、配对差毫秒；先对同题同档的重复汇总，再按题型/有图无图/档位比较。平均吞吐与配对收益分开，不用两组独立 P50 的比值冒充配对比值。
- 辅助指标：检索墙钟、单次调用墙钟、逻辑轮数/实际请求数、动作失败、格式失败、结束原因、响应长度、前缀长度、压缩次数及压缩轮耗时。
- 全部 run 都入账。超时按共同截止时长记录为删失观察，失败率单列；不把失败丢掉后只比较成功者，也不将超时值说成真实完成耗时。成功配对表可单列，但不能独自决定上线。
- 小样本展示逐题差值、中位数和最大值；尾部分位数标明样本数。E1/E2 的小样本不宣称稳定 P95，E3 的分格样本同样注明限制。
- 使用按题目聚类的重采样区间时，不把同题三次运行当作三个独立问题。若区间跨过无收益或时段结果相反，报告不确定并补样本；不事后挑题改变主集。
- 没有 token/cached 数据时，删除相应计算列或保留 unknown；不输出估计“缓存节约费用”。实付账单若能独立归因可作为附录，不是本期依赖。

### 10.2 采用门槛

以下是跑批前冻结的实用门槛，可在首个 dry-run 前由操作者调整并记录，不能看完结果后改：

1. **质量先行**：无新增越范围引用、虚报完整性、证据键错误、关键条件丢失；人工盲审确认必答项、事实及引用质量没有可复现回归。gold 只覆盖部分事实，不能仅凭 gold 命中率宣称全题等价。模型判分只辅助抽样。
2. **稳定性**：不得以失败/超时、错误提前停止增加换取提速。若有新增重大错误，先修复或退回较简单候选。
3. **时间收益**：完整 Ask 的主集配对耗时比中位数目标 ≤0.85；各主要题型/档位的系统性慢化超过 10% 需逐题解释和复测；总样本尾部不出现可重复恶化。上述是工程采用门，不是统计显著性声明。
4. **优先较简单候选**：若 P 与 D/L 的完整 Ask 配对中位收益差不足 5%，且质量相当，选 P。阶段压缩和历史增长必须有额外收益才值得维护。
5. **收益不确定时**：保持现有默认；允许保留测量与可选策略代码，不据 E1 的单项优势开闸。没有 cached 字段不阻塞做出采用/不采用的决定。

## 12. 必须覆盖的验证

使用纯函数、fakes、进程内客户端；普通门不调用真实模型。重点是可观察行为，不钉死源码行号或整份 prompt 文案。

- 同一 run 额度耗尽、方面状态改变、轮数增长，S/C 字节不变；新增 D 前已存在的 D 字节和顺序不变。
- 最终 provider-facing 消息检查覆盖 wrapper/schema；角色边界不变，动态值没有偷偷插到稳定块开头。
- P 与基线在冻结输入下传达同一批证据事实/执行限制；D 的省略有披露，完整用户约束不丢。
- 静态目录中已耗尽工具不能执行，后来有起点的合法工具可以出现于动态清单；Knowhow/legacy 不受新策略影响。
- 长历史触发预算前重建，目标比例无法满足时仍守硬预算；回退不增加调用/步骤、不清空结果或绑定。
- 已支撑方面撤销/冲突、旧枚举 complete 后变 conflict、同 key 摘录升级、非法键与未展示候选均正确处理。
- assessment 单项错误不吞合法动作，冲突重复不被静默去重成 supported；省略自评不追加专门调用。

## 13. 实验交付物与回退

每批实验输出：冻结 manifest、无正文的逐调用/逐 run 表、逐题配对表、质量盲审记录、聚合报告和异常清单。manifest 写明代码 SHA、optimization、公共执行基线、语料/意图快照、模型配置标签、随机种子、顺序、预算与截止时长。raw 内容留在操作者 `.local`，共享报告不包含它。

所有阶段都提供 dry-run：打印逻辑调用/完整 Ask 数、按实际重试配置计算的请求上界、沿用的单次超时与整批最大墙钟预算。运行达到整批预算时停止派发、按既有取消边界处理在途请求，并保留未完成/不成对标记；不得偷偷补跑到矩阵齐全后才报告。预计时长用先导样本估计，不用 flash 的历史每轮耗时预测 GLM 5.3。

报告第一页只回答四件事：最终候选是哪种模式；完整 Ask 比基线快多少；质量/失败/尾部是否退化；结论在哪些模型配置和题型上成立。E1 机制结果作为解释，不代替端到端结论。

默认 `REASONING_REFLECT_OPTIMIZATION=off`。选定策略逐步验证并由用户决定开启；任一质量或稳定性回归可立即回到 `off`，不做数据迁移。运行内发生上下文预算回退只影响该 run，并在统计中如实出现，不把它混算成始终使用 D 的结果。
