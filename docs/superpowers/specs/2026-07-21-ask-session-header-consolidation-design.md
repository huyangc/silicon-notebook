# Ask 会话顶栏合并设计

## 目标

把 notebook 工作区「问答」页现有的两行会话导航压缩成一行，减少固定栏杆对回答区域的占用，同时保留完整的会话管理能力。

## 已确认交互

- 仅在「问答」tab 显示会话入口。
- 顶栏右侧显示两个控件：`历史 N` 和 `+`。
- `历史 N` 继续打开现有会话管理面板；`N` 是当前 notebook 已保存的会话数量。
- `+` 的可访问名称和悬停提示都是「新会话」，点击后直接调用现有 `startNewSession`，不显示二次确认。
- 删除原第二行会话上下文栏，包括当前会话标题、重复的「新会话」按钮和重复的「历史 N」按钮。
- 会话管理面板中的新建、切换、重命名、删除和批量清理能力不变；当前会话仍在面板列表中高亮。

## 前端结构

新增一个小型 `AskSessionHeaderActions` 组件，接收会话数量、面板开关状态、打开/关闭面板回调和新建会话回调。`page.tsx` 的 workspace 顶栏在 Ask 模式下渲染该组件，其他三个主 tab 不渲染它。

聊天面板的固定网格从「顶栏 + 会话上下文栏 + 正文 + 输入区」改为「顶栏 + 正文 + 输入区」。会话管理面板仍绝对定位在聊天面板内，但上边缘改为紧贴 64px 顶栏下方；移动端使用同一锚点和单列会话卡片。

点击面板外部或按 Esc 关闭的既有逻辑继续识别 `历史 N` 按钮。已经删除的第二行选择器从外部点击白名单和响应式 CSS 中清理。

## 状态与数据流

本次不修改后端、API、会话模型或持久化行为：

1. `sessions.length` 驱动 `历史 N`。
2. 点击 `历史 N` 切换 `sessionPanelOpen`。
3. 点击 `+` 直接调用 `startNewSession`，由既有逻辑清空当前 turns、把 `conversationId` 置空并恢复默认 Ask 状态。
4. 下一次提问仍由既有 `/ask` 流程创建持久化会话。
