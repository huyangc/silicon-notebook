# Deep Report Credibility and Synthesis Plan

Date: 2026-08-01

## Problem statement

The current Deep Report pipeline retrieves and drafts every section independently,
then concatenates those drafts and asks the final editor for a summary. This makes
the report structurally prone to paper-by-paper summaries even when individual
facts are correctly cited. At the same time, the planner sees only a creation-order
sample of source titles, evidence sufficiency is dominated by hit counts, and the
reader cannot tell the difference between many citation anchors and many independent
documents.

The change has two inseparable goals:

1. make the evidence boundary visible and machine-auditable;
2. create a report-wide synthesis commitment before section prose is written.

The existing exhaustive-tier per-section outline scratchpad stays unchanged. Its
production adoption can be evaluated separately; it is not the coherence mechanism
for this work.

## Non-negotiable constraints

- Start from a dedicated worktree and branch.
- Preserve the confirmed intent, mandatory-topic bindings, and confirmed outline as
  authoritative user contracts.
- Add at most one model call per report, and only for detailed/exhaustive tiers.
- Keep retrieval and section writing parallel on either side of the new synthesis
  barrier.
- Any new structured output that is missing or malformed must fail open to the
  current report path; it must never fail the whole report.
- Keep exact citation anchors. Grouping is a bibliography/display concern, not an
  evidence-dedup shortcut.
- Do not call a semantic claim “supported” based only on punctuation or regex. The
  deterministic metric is **high-risk assertion citation coverage**.
- No database migration is required. Additive structures live in existing JSON
  report fields.
- User-facing copy uses “资料基础”, “引证覆盖率”, and “独立资料”; it must not expose
  KG/chunk/canonical terminology.

## Batch A — evidence boundary and honest coverage

### A1. Shared intent contract

Deep Report calls `plan_query_intent` and `finalize_query_intent` instead of keeping
a second parser. `result_scope` and `completeness_required` are persisted in the
existing understanding JSON and reach planning and sufficiency prompts.

Until report-side collection enumeration exists, `complete`, `aggregate`, and
`hybrid` reports disclose that they were generated by relevance retrieval and did
not perform a complete enumeration. Completeness wording must not be silently
downgraded.

Model-generated assumptions remain separately available as scope defaults. They are
not appended to retrieval text and prompts explicitly forbid treating them as
evidence.

### A2. Report corpus profile

Introduce one report-oriented profile service. It reuses the collection catalog's
scope and visible-source count, but does not pretend that the catalog contains
publication year, source type, hash, or title metadata.

The service consumes one bounded repository projection in both SQLite and
PostgreSQL and returns:

- visible source count;
- displayed/total source count with stratified representative titles;
- source-type and year distributions, including an explicit unknown-year bucket;
- conservative independent-document groups using equal nonblank file hash, then
  equal grounded paper title, then source id;
- duplicate inflation and metadata-coverage counts;
- bounded topic clusters derived deterministically from existing catalog/source
  metadata, with representatives;
- an explicit identity-uncertain count when metadata cannot safely merge likely
  duplicates.

The same persisted profile feeds the planner, the fixed “资料基础” report section,
and the front-end disclosure. The old naked `LIMIT 20` path is removed.

### A3. Sufficiency and evidence diversity

Sufficiency uses relevant independent-document groups, relevance, and distribution
across the section's approved directions. KG and element hit counts remain diagnostic
signals only; base-tier hits are not described as independent authority.

The deterministic fallback is conservative and configurable. It must never label a
section sufficient solely because many objects were extracted from one document.

### A4. High-risk assertion audit

After a section draft is produced, scan prose sentences/table rows for bounded,
observable high-risk forms: numbers with units, complexity notation, explicit
rankings/superlatives, and absolute comparative claims. Exclude headings, code,
formula-only blocks, and sentences explicitly marked as inference or general
knowledge.

For every audited assertion, determine whether the same sentence/table row contains
a valid emitted `[k]` marker. Persist cited/total counts and ratio. If the uncited
ratio exceeds the configured threshold, cap the section at `overview`; never claim
that this regex audit establishes semantic entailment.

### A5. Citation concentration and bibliography grouping

Keep anchor-level references and click-through behavior. Add deterministic metrics:
anchor count, independent-document count, Top-1 share, and duplicate inflation.
Render the bibliography grouped by conservative document group so multiple anchors
from one paper cannot visually masquerade as independent sources.

### A6. Fair final-editor input

Replace “first 2,000 characters of every section” with a deterministic bounded
allocator that supplies each section's thesis-bearing beginning, conclusion-bearing
ending, claim/audit metadata, and an equal minimum share. This fixes positional
blindness without an extra model call.

## Batch B — report-wide synthesis before prose

### B1. Optional frame contract

For comparison, review, and classification-shaped requests, the existing STORM
planning call may return an optional frame:

```json
{
  "subject_kind": "...",
  "facets": [{"id":"...","name":"...","values":["..."],"exclusive":true}],
  "axes": [{"id":"...","name":"...","condition_fields":["..."]}],
  "instance_policy": "..."
}
```

The frame is bounded and stored in `understanding.report_frame`. It appears beside
the outline, is editable in the same confirmation operation, and becomes
authoritative once confirmed. Missing/invalid frames preserve existing behavior.
No separate frame-validation model call is added.

### B2. Retrieve–synthesize–write barrier

Refactor generation from:

`parallel(retrieve + draft) -> concatenate -> final editor`

to:

`parallel retrieve -> one global synthesis call -> parallel draft -> final editor`.

Detailed and exhaustive tiers receive the one new synthesis call. Lower tiers and
any synthesis failure use the previous independent drafting path.

The synthesis input contains the frozen intent/frame/outline and bounded evidence
cards from every section. Evidence is keyed by analytical question, facet, and
comparison axis rather than by document order.

### B3. Synthesis blueprint

The new call returns a bounded blueprint:

```json
{
  "central_answer": "...",
  "shared_definitions": [{"term":"...","definition":"...","evidence_keys":["..."]}],
  "claims": [{
    "id":"c1", "statement":"...", "type":"fact|comparison|trend|inference|general",
    "facet_id":"...", "evidence_keys":["..."], "counterevidence_keys":["..."],
    "conditions":["..."], "owner_section_id":"..."
  }],
  "sections": [{
    "section_id":"...", "thesis":"...", "claim_ids":["c1"],
    "must_contrast":["..."], "handoff":"...", "do_not_repeat":["c2"]
  }]
}
```

Server validation enforces existing section ids, mandatory-topic retention, legal
evidence keys, legal frame ids, one claim owner unless explicitly shared, and all
bounds. A malformed blueprint is discarded atomically.

### B4. Section drafting contract

Each writer receives the same central answer and shared definitions, plus only its
owned claims, contrasts, handoff, and no-repeat list. It must lead with a conclusion,
synthesize agreement/disagreement and conditions, avoid source-by-source narration,
attribute single-source findings as conditional, and avoid cross-paper rankings
unless conditions are comparable.

### B5. Claim ledger bound to emitted prose

The section writer schema adds at most 24 claims. Each claim contains the exact
emitted statement (or a stable statement hash), type, entities, frame assignments,
evidence keys, conditions, and confidence. Deterministic validation requires the
statement to exist in the markdown and the cited markers to occur in the same
sentence/table row.

Missing or malformed claims keep the markdown and mark the ledger unavailable.
Conflicts are checked only for exclusive confirmed facets. Trend source-family
counts cap wording eligibility but never prove a trend on their own.

### B6. Final editor

The editor receives the frame, validated blueprint, complete bounded claim ledger,
high-risk audit, cross-section exclusive-facet conflicts, and fair prose excerpts.
It checks definition consistency, summary/body conflict, unsupported trend wording,
and time-boundary limitations. It remains audit-only and never rewrites body
sections or introduces facts. The executive summary is generated only after this
audit context is assembled.

## Validation

Deterministic fixtures cover:

- broad taxonomy, explicit complete listing, multi-object comparison,
  time-sensitive review, and deliberately biased corpus;
- shared-intent persistence and truthful ranked-only completeness disclosure;
- profile parity between SQLite and PostgreSQL;
- duplicate-family inflation and citation concentration;
- high-risk cited/uncited assertions and non-applicable prose;
- frame edit preservation and silent-drop mutation;
- blueprint malformed-output fallback and illegal evidence-key rejection;
- single-source trend wording cap and cross-section exclusive-facet conflict;
- claim statement/anchor binding and malformed-ledger fallback;
- front-end frame/profile/support display.

Depth is expected to improve independent-source coverage, but stochastic end-to-end
monotonicity is an observation, not a hard invariant. The hard invariant applies to
the deterministic selector given the same question, outline, and candidate pool:
raising its evidence budget must not reduce selected independent-document coverage.

## Deferred follow-up

- DOI/arXiv/title/hash/file-family canonicalization and family-level evidence quotas;
- true report-side complete enumeration;
- targeted re-retrieval driven by audited weak claims;
- product decision on renaming the “穷尽” tier;
- operational paper-metadata backfill and duplicate-row cleanup.
